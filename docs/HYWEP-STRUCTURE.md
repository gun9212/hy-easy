# HY-WEP 화면 구조 (2026-11-10 실측)

> Safari에서 운영자 계정으로 직접 확인한 결과. 실제 기업명·개인 지원 정보는 기록하지 않고 형식만 적는다.
> 선택자(`worker/selectors.verified.json`)는 이 문서를 근거로 작성하되, DOM 속성은 개발자 도구로 한 번 더 확인해야 한다.

## 1. 로그인 흐름

| 단계 | URL | 관찰 |
|---|---|---|
| 1 | `https://hywep.hanyang.ac.kr/index.do` | 비로그인 첫 화면. 학생/교수/실습기관/지원센터 탭과 `로그인` 링크. 공개 공지 5건(제목에 마감일 포함) |
| 2 | `https://api.hanyang.ac.kr/oauth/login` | 한양대 포털 OAuth 인증 페이지 (창 제목 "한양대학교 인증센터") |
| 3 | `https://hywep.hanyang.ac.kr/...` | 인증 후 HY-WEP MY PAGE로 복귀 |

- **포털 세션이 살아 있으면 비밀번호 입력 없이 SSO로 통과한다.** 이번 확인에서는 브라우저에 포털 세션이 있어 로그인 폼을 거치지 않았다.
- 인증 단계에서 JS `alert`이 뜰 수 있다: 3개월 이상 비밀번호를 바꾸지 않은 계정에 "비밀번호 변경 안내". 수집기는 `page.on('dialog')`로 이 알림을 닫아야 한다.
- **로그인 폼 자체(ID/PW 입력, CAPTCHA·2차 인증 여부)는 아직 확인하지 못했다.** 포털에서 로그아웃한 상태로 한 번 더 확인해야 한다.

## 3. 공고 상세 — 팝업 창

- 부서 링크 클릭 시 **새 창**으로 열림. URL은 `https://hywep.hanyang.ac.kr/compjoinmanage/view_stu.do`이며 **쿼리스트링이 없다** → POST 또는 JS 함수로 공고 ID를 넘기는 구조. 수집기는 링크 `href`/`onclick`에서 ID를 추출해야 한다.
- 레이아웃: `실습기관 정보` 머리말 아래 **라벨 셀 / 값 셀 표**. 한 행에 라벨·값 쌍이 1~2개.

## 4. MY PAGE (참고)

로그인 직후 화면. 본인 지원 내역 표(지원차수, 실습기관, 부서, 면접/선발여부 `심사전` 등)가 있다.
→ 향후 "내 지원 상태 자동 동기화"의 근거가 될 수 있으나, **운영자 계정의 개인 정보이므로 수집 대상이 아니다.** 사용자별 동기화는 별도 설계가 필요하다.
